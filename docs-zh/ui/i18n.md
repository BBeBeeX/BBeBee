# i18n 贡献指南

BBeBee 里用户可见文案的国际化做法。规范性规则在
[`rules/i18n.md`](../../rules/i18n.md)（英文），这里是面向贡献者的操作说明。

## 模型

- 每个 UI 文案都是一个 **key**，永远不要写硬编码字面量：`t('namespace:path.to.key')`。
- key 放在 `@bbebee/plugin-i18n` 自带的 **catalogue** 里
  （`packages/feature/plugin-i18n/src/locales/`）：`app` namespace 用
  `en.json`/`zh.json`，每个插件 namespace 一个 `<ns>.json`（`{en, zh}` 并列）。
- 运行时 `ctx.i18n` 按 key 粒度解析 `t()`：当前语言 → `en` → key 本身。
  缺 key 时降级为可读的标识符，永远不会渲染出空白。
- 不引入第三方 i18n 库，`ctx.i18n` 服务是唯一的机制。

## key 格式

`namespace:path.to.key`，例如 `t('library:playlistDetail.addTracksToFill')`。

- **namespace** 是所属插件的领域（`library`、`sources`、`settings`……），
  共享 kit（`packages/ui/ui-kit-*`、`apps/*`）用 `app`。不要把一个插件的
  key 塞进另一个插件的 namespace，也不要为了省事全堆进 `app`。
- **path** 按界面/组件分组（`playlistDetail`、`nowPlayingStyles`……）。
- **key** 用小驼峰，根据英文文案提炼。
- 插值用 `{param}` 占位符：`t('x:y.deleteItem', { title })`。
  不要拼接句子——中英文语序不同，拼出来的必错。复数拆成 `one`/`other`
  两个 key，调用方按数量选完整的字面量 key（禁止运行时拼 key）。

## 写 UI 代码

```tsx
// 有 ctx → 用 hook。永远不要直接读 ctx.i18n（service 缺失时会抛错，
// hook 做了优雅降级）。
const { t } = useI18n(ctx)
return <button aria-label={t('library:index.addFolder')}>{t('library:index.addFolder')}</button>
```

- 没有 `ctx` 的组件，由所属界面把 `ctx` 透传下来（既定做法），
  或由调用方传入翻译好的文案。
- `en` catalogue 的值是**逐字搬运**的源文案——照搬，不要润色。
  抽取时不要改写英文。
- `zh` 翻译遵守 `rules/i18n.md` §4 的术语表。
- 不要抽取：注释、日志、测试断言、React key、存储 key、URL、
  品牌名、数据样例、示例值。

## 无 ctx 的窗口（desktop-lyrics / mini-player）

这两个桌面端独立窗口（基于 Tauri Webview 窗口）不启动完整 Cordis 应用，没有 `ctx`，用不了
`useI18n`。它们走 preload 的 `locale` bridge：

```tsx
// 主窗口的渲染进程在语言变化时经 bridge 推送，hook 订阅后自动重渲染，
// 切换语言无需重启窗口。
const { t } = useBridgeLocale() // 来自 @BBeBee/ui-kit-desktop
```

- `t()` 的解析规则与 service 一致（当前语言 → `en` → key 本身），
  数据来自 `@bbebee/plugin-i18n` 导出的 `BUILT_IN_CATALOGUES`
  （与 service 注册的是同一批 JSON）。
- bridge 覆盖不到第三方插件运行时 `register()` 的 catalogue——
  这两个窗口只读内置 key（`app:*`、`miniPlayer:*`），不受影响。
- bridge 缺失时（单测、storybook）降级渲染英文，与迁移前的硬编码
  文案逐字节一致，永不抛错。

## 第三方插件

第三方 catalogue **不进**静态检查，运行时注册即可：

```ts
ctx.i18n.register('myPlugin', {
  en: { 'panel.title': 'My panel' },
  zh: { 'panel.title': '我的面板' },
})
```

第三方 catalogue 不全时按 key 粒度降级（缺 key 走 `en`，再缺走 key
本身），不影响其余界面。

## 语言选项的母语名

设置页的语言选项用**母语显示名**（macOS / iOS / 浏览器设置的惯例）：
`中文`、`English` 不翻译——它们是专有名词，在任何界面语言下都这么
显示（看不懂当前界面语言的用户也能找到自己的语言）；只有
母语选项数据放在独立 `.ts` 模块中（如 `language-options.ts`）。

## 门禁（都在 CI 里）

| 门禁 | 命令 | 检查内容 |
|---|---|---|
| 语言 parity | `pnpm check:locales` | 所有自带 catalogue 的 en/zh key 集合一致 |
| 无硬编码文案 | `pnpm check:i18n-gate` | tsx 里零硬编码 UI 文案 |
| 全量门禁 | `pnpm check` | typecheck + lint + test |

目前代码库已实现零硬编码文案与零白名单。
如后续确有无法避免的例外，可在仓库根配置 `i18n-allowlist.txt`，
每行 `file :: text` 并附 `# reason`。保持最少。
