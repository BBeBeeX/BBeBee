# 国际化架构 (`ctx.i18n`)

> **本文解答的问题。** 桌面端与移动端如何在不引入第三方 i18n 库的前提下，组织、解析并实时切换界面文案（`@BBeBee/plugin-i18n`，Layer 4）。

---

## 1. 服务契约 (`I18nService`)

接口声明位于 [`packages/protocol/src/services/platform.ts`](../../packages/protocol/src/services/platform.ts)，由 `@BBeBee/plugin-i18n` 实现：

```ts
export interface I18nService {
  readonly locale: string
  t(key: string, params?: Record<string, string | number>): string
  register(namespace: string, catalogues: Record<string, Record<string, string>>): Disposable
  onLocaleChange(cb: (locale: string) => void): Disposable
}

declare module 'cordis' {
  interface Context {
    i18n: I18nService
  }
}
```

语言切换通过 `ctx.settings`（`AppSettings.language: 'zh' | 'en' | 'system'`）驱动，而非在 `ctx.i18n` 上增加 setter。当 `settings.language` 变更时，`plugin-i18n` 会重新解析 `locale` 并通知所有 `onLocaleChange` 订阅者。

---

## 2. Key 格式与 Namespace 约定

### 2.1 Key 语法

所有翻译 key 均遵循 `namespace:path.to.key` 格式：

```ts
ctx.i18n.t('app:common.confirm')
ctx.i18n.t('registry:filter.showThirdParty')
ctx.i18n.t('settings:github.endpointLabel', { index: 1 })
```

- **分隔符：** 第一个 `:` 将 `namespace` 与点分路径 `path` 分开。
- **嵌套与扁平 JSON：** 内置 JSON 语言包支持嵌套对象（如 `{ "common": { "confirm": "确认" } }`），加载时会自动展平为点路径（`common.confirm`）；通过 `ctx.i18n.register()` 动态注册的语言包使用扁平点路径（`{ "filter.showThirdParty": "..." }`）。
- **复数处理：** 不使用 ICU 语法。调用方按数量显式选择 key（如 `items.one` / `items.other`）并传入 `{ count }`。

### 2.2 内置 Namespace

`@BBeBee/plugin-i18n` 在 `packages/feature/plugin-i18n/src/locales/` 下内置以下语言包：

| Namespace | 文件路径 | 用途 |
|---|---|---|
| `app` | `src/locales/en.json`、`src/locales/zh.json` | 通用动作（确认/取消/重试/保存/删除）、状态文案（加载中/空状态/错误/离线）与通用单位 |
| `registry` | `src/locales/registry.json` | 社区内容中心筛选栏（`registry:filter.*`）及路由标题（`registry:route.discover`） |
| `settings` | `src/locales/settings.json` | 设置界面文案（如 `settings:github.*`） |

### 2.3 参数插值 (`{var}`)

模板中使用 `{name}` 占位符，由 `params` 替换：

```ts
ctx.i18n.t('settings:github.endpointLabel', { index: 2 })
// en → "Acceleration endpoint 2"
// zh → "加速线路 2"
```

若 `params` 未提供或缺少对应字段，`t()` 会保留 `{name}` 原文占位，并通过 `ctx.logger.warn` 按 `(key, param)` 粒度去重告警一次。

## 3. Locale 解析与按 Key 粒度 Fallback

### 3.1 Locale 解析链 (`settings.language`)

1. **显式语言（`'zh'` 或 `'en'`）：** 经 BCP 47 协商后直接采用。
2. **跟随系统（`'system'`）：** 读取 `ctx.device.locale`（桌面端由 `core-device-tauri` / `@tauri-apps/plugin-os` 提供，移动端由 `core-device-expo` / `Intl` 提供；`plugin-i18n` 本身不直接导入任何平台 SDK）。
3. **BCP 47 逐级协商 (`negotiateLocale`)：** 将下划线转为连字符并转为小写，从右向左逐段剥离（如 `zh-Hant-HK` → `zh-hant-hk` → `zh-hant` → `zh`、`fr-FR` → `fr-fr` → `fr`），匹配已注册语言包；若仍无匹配则回退到 `'en'`。

### 3.2 按 Key 粒度 Fallback (`t()`)

每次调用 `t(namespace:path)` 均按单个 key 独立回退：

```
当前 locale 语言包 → 'en' 语言包 → 返回 key 原文
```

- **禁止整包降级：** 若 `zh` 缺少 3 个 key，仅这 3 个 key 回退显示英文，其余界面保持中文。
- **第三方插件隔离：** 仅注册了英文语言包的第三方插件会以英文显示自身文案，不影响宿主应用其余部分的中文显示。
- **永不返回空值：** `t()` 永不返回 `""` 或 `undefined`。当前语言与 `'en'` 均未命中时，通过 `ctx.logger.warn` 按 key 去重告警一次并返回 `key` 本身。

## 4. 插件如何注册 Catalogue (`ctx.i18n.register`)

功能插件或第三方插件可在 `ctx.effect()` 中调用 `ctx.i18n.register(namespace, catalogues)` 注册专属 namespace，确保插件卸载时自动清理：

```ts
import type { Context } from '@BBeBee/protocol'

export const name = 'plugin-my-feature'
export const inject = ['i18n']

export async function apply(ctx: Context) {
  ctx.effect(() =>
    ctx.i18n.register('my-feature', {
      en: {
        'header.title': 'My Feature',
        'status.items': '{count} items',
      },
      zh: {
        'header.title': '我的功能',
        'status.items': '{count} 项',
      },
    }),
  )
}
```

- **Namespace 隔离：** 同一 namespace 下的多次注册按栈顺序叠加（同 key 后注册者优先）。调用返回的 `Disposable` 仅移除该次注册的词条，不污染其他插件或内置词条。

## 5. UI 接入指南 (`useI18n`)

`@BBeBee/ui-kit-desktop` 与 `@BBeBee/ui-kit-mobile` 均导出 `useI18n(ctx: Context)` hook：

```ts
import { createElement as h } from 'react'
import type { Context } from 'cordis'
import { useI18n } from '@BBeBee/ui-kit-desktop' // 移动端使用 '@BBeBee/ui-kit-mobile'

export function ExampleView({ ctx }: { ctx: Context }) {
  const { t, locale } = useI18n(ctx)
  return h('button', { type: 'button' }, t('app:common.confirm'))
}
```

- **不引入新的 React Context Provider：** 遵循三包 UI 约定，组件通过 props 接收 `ctx` 并直接传给 `useI18n(ctx)`。
- **无刷新实时重渲染：** `useI18n` 内部订阅 `ctx.i18n.onLocaleChange`，卸载时自动取消订阅；当 `locale` 变化时同步更新 `t` 引用，确保依赖 `[t]` 的 `useMemo` 派生文案自动重算。
- **路由与托盘标题 (`RouteContribution.title`)：** 插件贡献路由时可将 `title` 设为 i18n key（如 `title: 'registry:route.discover'`），桌面端（`Shell.tsx`、`TopBar.tsx`）与移动端（`App.tsx`）均通过 `useI18n(ctx)` 自动解析包含 `:` 的路由与托盘标题。

## 6. 语言包完整性门禁 (`check-locales.mjs`)

内置语言包（`en.json` 与 `zh.json`，以及 `registry.json`、`settings.json` 中的 `en`/`zh` 分支）由以下脚本进行完整性校验：

```bash
pnpm check:locales
# 或：node packages/feature/plugin-i18n/scripts/check-locales.mjs
```

任何在 `en` 中存在但在 `zh` 中缺失（或反之）的点路径 key，以及任何空字符串值，均会输出 error 并以非零退出码终止（已接入 `.github/workflows/ci.yml`）。通过 `ctx.i18n.register()` 动态注册的第三方语言包不纳入静态门禁，由运行时按 key 粒度 fallback（§3.2）兜底。

## 7. 接入 Checklist

- [ ] Key 命名遵循 `namespace:path.to.key`（小驼峰点路径，按领域划分 namespace）。
- [ ] 向 `packages/feature/plugin-i18n/src/locales/*.json` 新增词条时，同时补齐 `en` 与 `zh`。
- [ ] 运行 `pnpm check:locales` 确认中英词条集合完全一致且无空串。
- [ ] 插件自注册语言包时，务必将 `ctx.i18n.register(...)` 包裹在 `ctx.effect()` 中或作为 disposer 返回。
- [ ] UI 组件从 `@BBeBee/ui-kit-desktop` 或 `@BBeBee/ui-kit-mobile` 导入 `useI18n(ctx)`（严禁引入第三方 i18n 库）。
- [ ] 单测覆盖 `settings.language` 在 `'en'` 与 `'zh'` 之间切换时组件的实时重渲染表现。
