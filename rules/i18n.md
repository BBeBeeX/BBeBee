# i18n Rules (L2)

Normative rules for user-visible strings in BBeBee. Infrastructure: `ctx.i18n`
(`packages/feature/plugin-i18n`); React binding `useI18n(ctx)` in
`@BBeBee/ui-kit-desktop` / `@BBeBee/ui-kit-mobile`.

> **L2 · When to read**: when adding or changing any user-visible text in
> `apps/*` or `packages/ui/*`.
> **What goes wrong without it**: hardcoded strings that never translate,
> runtime-concatenated keys, one English term translated three ways.

## 1. Key format & namespaces

- Format: `namespace:path.to.key` — e.g. `t('app:common.confirm')`.
- `app`: shell-shared strings (`common.*` lives here; extend under `common.*`, no new top level).
- One namespace per UI-bearing plugin (`settings`, `registry`, `player`, `queue`,
  `library`, `nowPlaying`, `lyrics`, `download`, `history`, `sources`, `theme`,
  `dsp`, `visualizer`, `share`, `album`, `localScanner`, `miniPlayer`,
  `inspector`). Never dump plugin strings into `app` to save time.
- Key path: semantic English lowerCamelCase (`player.queue.empty.title`).
  No pinyin, no numeric ids.
- Catalogue files: `packages/feature/plugin-i18n/src/locales/<namespace>.json`
  with side-by-side `en`/`zh` objects (see `settings.json`).

## 2. What gets a key

In: JSX text, `placeholder`/`title`/`aria-label`/`alt`/`label` props, buttons,
menus, tabs, dialogs, toasts, empty states, validation messages, settings
titles/descriptions, route titles, ternary branches with user text.

Out: comments, logs (`ctx.logger.*`), test fixtures/assertions, dev-only error
objects, CSS values, icon glyphs, data content (artist names, file names),
`docs-zh/`.

## 3. Interpolation & dynamics

- Params: `t('ns:path.key', { name })` → `{name}` in catalogue. Missing param
  keeps the placeholder visible (warns once).
- **Never build keys at runtime** (`t('app:' + s)`). Branch on full literal keys.
- Plurals: split keys (`items.zero`/`items.one`/`items.other`); caller picks.
- No string-concatenated sentences — Chinese/English word order differs.

## 4. Translation discipline

- `en` catalogue: copy the current English **verbatim** — no rewording.
- `zh` terminology (one translation per term, changes need justification):

| EN | ZH |
|---|---|
| Search | 搜索 |
| Settings | 设置 |
| Playlist | 播放列表 |
| Queue | 播放队列 |
| Favorite(s) | 收藏 |
| Source | 音乐源 |
| Accelerate / acceleration | 加速 |
| Library | 音乐库 |
| Download | 下载 |
| Discover | 发现 |
| Diagnostics | 诊断 |
| Task(s) | 任务 |

## 5. Runtime contract

- Components use `useI18n(ctx)` (`{ locale, t }`); **never** read `ctx.i18n`
  directly (Cordis throws when the service is absent; the hook degrades to
  returning the key).
- Missing key falls back per key: `locale → en → key`. Never whole-screen
  downgrade. BCP 47 chain (`zh-HK → zh → en`) preserved.
- Third-party catalogues register via `ctx.i18n.register()`; not covered by
  the static parity gate, runtime fallback applies.

## 6. Tooling & gates

- `pnpm check:locales` (`scripts/check-locales.mjs`): en/zh key parity for all
  shipped catalogues, non-zero exit on mismatch. CI runs it.
- `scripts/inventory-ui-strings.mjs`: read-only UI-string inventory
  (`--root . > inventory.tsv`); deterministic — two runs must diff empty.
- CI also forbids new hardcoded UI strings in `apps/*/src`, `packages/ui/*/src`
  (see `i18n-allowlist.txt` for reviewed exceptions; empty by default).
